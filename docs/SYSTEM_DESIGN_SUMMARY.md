## Multi-agent architecture

### Agent 1: Code smell detection agent
- **Technology**: SonarQube
- **Location**: `sonarqube/commit_scan.py`
- **Function**: Detects 8 types of code smells with severity levels

### Agent 2: Test existence verification agent
- **Technology**: LangGraph + LLM
- **Location**: `agents/java_test/agent.py`
- **Function**: Verifies test coverage for smelly methods

### Agent 3: Test generation agent
- **Status**: Placeholder (not main research focus)
- **Function**: Would generate tests for uncovered code

### Agent 4: Smell prioritization agent
- **Technology**: NetworkX + Dependency rules
- **Location**: `scripts/prioritize_smells.py`, `agents/dependency_analysis/agent.py`
- **Function**: Calculates refactoring priority using PZ = Severity + Positive Impact
- **Output**: Prioritized sequence and visualization graphs

### Agent 5: Refactoring execution agent
- **Technology**: LangGraph + LLM
- **Location**: Part of rminer evaluation workflow
- **Function**: Applies refactorings in priority order

### Agent 6: Test execution and verification agent
- **Technology**: Reuses Agent 2's test execution
- **Function**: Validates refactorings preserve behavior

## Priority calculation formula

```
PZ_i = Severity_i + Σ(w_impact for each positive dependency)
```

Where:
- Severity: HIGH=3, MEDIUM=2, LOW=1
- w_impact = 2 per positive dependency
- Greedy selection: max(PZ) at each iteration

## Dependency rules

### Positive dependencies (Solving)
- Long Method → Switch Statement, Duplicated Code, Feature Envy, etc.
- Large Class → Data Clumps, Feature Envy, Bad Class Content
- Long Parameter List → Data Clumps

### Negative dependencies (Risk)
- Long Parameter List → Data Class
- Large Class → Long Method, Data Class, Inappropriate Intimacy
- Complex Method → Long Method, Long Parameter List

## Complete workflow

1. **Agent 1**: Scan commit with SonarQube → Detect smells
2. **Agent 2**: Check test coverage for smelly methods
3. **Agent 4**: Analyze dependencies → Calculate PZ scores → Generate priority sequence
4. **Visualization**: Create dependency graphs
5. **Agent 5**: Apply refactorings in priority order
6. **Agent 6**: Run tests after each refactoring
7. **Metrics**: Calculate code quality improvements
8. **MLflow**: Log all results for analysis

## Key innovation

The system implements a **dependency-aware prioritization** strategy based on Markovič & Polášek's theory, where refactoring order is optimized to:
1. Maximize positive cascading effects (solving multiple smells)
2. Minimize negative side effects (creating new smells)
3. Prioritize high-severity smells with high impact

This is visualized through NetworkX graphs showing green edges (positive dependencies) and red edges (negative dependencies).
